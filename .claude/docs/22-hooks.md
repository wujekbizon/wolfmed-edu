# Custom Hooks Catalog

[← Back to index](./README.md)

All 60 files in `src/hooks/`, one hook per file. Every entry below is read directly from source — signature, return shape, and any non-obvious behavior (races, cleanup, dedup) called out explicitly, not guessed from the name. Grouped by domain.

Naming collision to know about: `src/hooks/useStore.ts` (a generic hydration-safe Zustand selector wrapper, `useStore(store, callback)` — delays returning the selected value until after mount to avoid SSR/CSR hydration mismatch) is a different thing from `src/store/useStore.ts` (an actual Zustand store instance — see [`27-state-stores.md`](./27-state-stores.md)). Import paths disambiguate them (`@/hooks/useStore` vs `@/store/useStore`), but the shared name is a trap when skimming imports.

## Forms & mutations

| Hook | Signature → Return | Behavior |
|---|---|---|
| `useOnFormSuccess` | `(state: FormState, onSuccess: () => void) => void` | Fires `onSuccess` once per successful `useActionState` result. Dedupes on `state.timestamp` (via a ref) rather than `state.status` alone — the form-state object survives unrelated re-renders, which would otherwise re-fire the callback every time. `onSuccess` itself is stashed in a ref so a new closure passed on every render doesn't retrigger the effect. |
| `useInvalidateOnSuccess` | `(state: FormState, queryKeys: QueryKey[]) => void` | Thin wrapper around `useOnFormSuccess`: on success, calls `queryClient.invalidateQueries({ queryKey })` for every key in `queryKeys`. The standard way a mutation keeps a React Query-backed list in sync (Golden Rule #5). |
| `useToastMessage.tsx` | `(formState: FormState) => JSX.Element` (default export, also exports `showToast(status, message)`) | Fires a `react-hot-toast` (`.error`/`.success`) when `formState.timestamp` changes and `message` is non-empty — same timestamp-dedup pattern as `useOnFormSuccess`. Returns a `<noscript>` fallback (red/green inline text) so the status is visible with JS disabled — this is the `noScriptFallback` rendered inside every canonical form. `showToast(status, message)` is the same firing logic exposed as a plain function, for callers outside a component's render (event handlers, other hooks — e.g. `useDiagnozyExam`, `useWypelnijForm` both call it directly instead of returning state for a `useToastMessage` call). |

## Test-taking & timers

| Hook | Signature → Return | Behavior |
|---|---|---|
| `useCountdown` | `(initialTime: {days,hours,minutes,seconds}) => {days,hours,minutes,seconds}` | Generic countdown. Anchors to a real end timestamp (`Date.now() + total*1000`, stored in a ref) rather than decrementing a counter by 1 each tick — keeps the displayed time accurate even if the browser throttles the tab or skips ticks (drift-free). Stops and clears its own interval at zero. |
| `useCountdownTestTimer` | `({expiresAt?, durationMinutes?, warningThresholdSeconds=300}) => {timeLeft, isWarning, isTimeUp}` | Wall-clock-anchored countdown. Theory-test sessions pass the absolute server `expiresAt`, so reload/remount cannot restart the clock. Other exam flows may pass a duration. `isWarning`/`isTimeUp` are derived from `timeLeft`. |
| `useSessionHeartbeat` | `(sessionId: string \| null) => void` | `HEARTBEAT_INTERVAL = 2 * 60 * 1000` (2 min). Posts immediately, every interval, and when the tab becomes visible. A `404` redirects to `/panel/testy`. Cleanup only removes its timer/listener; it never mutates session status. |
| `useBeaconCleanup` | `(sessionId: string \| null) => void` | Owns intentional anti-cheat expiry. Sends `/api/session/expire` immediately on `document.hidden` (tab switch, minimize, phone lock) and `pagehide` (close/reload). Real component unmount also expires after one task; a same-session Strict Mode/Fast Refresh remount invalidates the stale cleanup generation, preventing false expiry during development or React lifecycle replay. |
| `useGeneratedTest.tsx` | `(tests: Test[], numberTests: number \| null) => Test[]` | Picks a random subset via `generateRandomTests()` whenever `tests`/`numberTests` changes; resets to `[]` when `numberTests` is falsy. |
| `useSortedTests` | `(tests: CompletedTest[]) => CompletedTest[]` | Reads `sortOption` from `useSortCompletedTestsStore` (Zustand). `useMemo`'d sort over 4 modes (`dateAsc`/`dateDesc`/`scoreAsc`/`scoreDesc`); missing `completedAt` falls back to `1970-01-01` so unparseable dates sort first, not crash. |
| `useQuestionsQuery` | `({questions, searchQuery, currentPage, questionsPerPage}) => {currentQuestions, totalPages, isLoading, totalFilteredQuestions}` | The React Query search/paginate pattern Golden Rule #5 mandates. Debounces `searchQuery` (250ms via `useDebouncedValue`), caches the unfiltered pool under `['categoryQuestions', category]` (`initialData` seeded, 10min `staleTime`), filters into a second query key `['filteredCategoryQuestions', category, debouncedTerm]`, then paginates the result with `useMemo`. `isLoading` is hardcoded `false` — both queries have `initialData`/synchronous `queryFn`s, so there's never a loading state to report. |

Registers a Lexical update listener; on a non-collapsed range selection, reads the native `window.getSelection()` bounding rect. A ref (`prevRectRef`) skips `setState` when the rect hasn't actually moved, avoiding a re-render of the selection tooltip on every editor tick while a selection is just being held. |

## Mind maps & diagrams (Excalidraw / `@xyflow/react`)

| Hook | Signature → Return | Behavior |
|---|---|---|
| `useMindMapCanvas` | `({root, onRootChange, onExplain}) => {wrapperRef, nodes, edges, layout, setLayout, selectedId, selectedNode, selectedIsLeaf, selectedPath, onNodeClick, clearSelection, handleMastery, handleExplain, handleExport, handleExpandAll, handleCollapseAll, handleResetView}` | The mind-map editor's core controller. Builds the React Flow graph (`nodes`/`edges`) from the tree via `buildFlowGraph(root, layout, selectedId)`, memoized. `onNodeClick`: every node click selects it (opens the detail card); a branch node (has children, or is collapsed) additionally toggles its subtree via `toggleNodeCollapse` and queues a matching camera move through `useMindMapFocus`. Re-fits the camera on layout mode changes (an explicit user action) but deliberately not on collapse/expand, which gets its own focused move instead of a full re-fit. `handleExport` rasterizes the current viewport to PNG via `exportMindMapPng`. |
| `useMindMapFocus` | `(nodes: Node[]) => (request: FocusRequest) => void` | Animated camera control, queued rather than applied immediately: a request is stashed in a ref and applied in a `useEffect` keyed on `nodes` — necessary because expand/collapse changes node positions only once the rebuilt layout has actually committed, so focusing before that would target stale coordinates. Three request kinds: `'reset'` (fit the whole tree), `'leaf'` (center + zoom on one node, offset to avoid `NodeDetailCard` covering it — `+150px` X on desktop, `+90px` Y on mobile), `'expand'`/`'collapse'` (fit the clicked node plus, for expand, its newly-revealed children). |
| `useAttachExplanationToMindMap` | `({origin, state, isPending}) => void` | Writes an AI-tutor answer back onto the mind-map node that requested it (via `origin.mapCellId`/`origin.nodeId`), so the explanation persists inside the map's own content rather than only in the RAG cell that generated it. Dedupes on `state.timestamp` (ref-based, same pattern as `useOnFormSuccess`). No-ops if the target cell isn't currently a `mindmap`-type cell (e.g. deleted since the question was asked). |
| `useInsertGeneratedCell` | `() => (afterCellId, cellType, content) => Promise<void>` | Inserts an AI-tool-produced result as a new board cell after a given cell. For any type except `'flashcard'`, just calls `useCellsStore`'s `insertCellAfterWithContent` directly. For `'flashcard'`: parses the generated cards (`parseFlashcardContent`), calls `createGeneratedDeckAction(topic, flashcards)` to **persist them to the DB first**, then inserts a cell whose content is only `{deckId}` — mirrors `useFlashcardCell`'s DB-not-blob storage pattern. Shows an error toast and returns early if generation or the DB write fails. |
| `useMermaidScene` | `(cellId, content, excalidrawAPI, fitAuto) => {scene, isConverting, hasFailed, retry, onChange, onPointerUp}` | Owns Mermaid→Excalidraw conversion for a diagram cell. On a pending Mermaid source (`cell.kind === 'source'`), converts async via `convertMermaidScene()`, persists the result back into the cell (`updateCell` + `serializeDiagramCell`), and applies it to the live canvas via `excalidrawAPI.updateScene` — pushed explicitly rather than via `initialData`, since Excalidraw only reads `initialData` once (an earlier version relied on remounting the whole canvas to work around this, which the source comment notes was accidental and would have broken under a different loading-state flow). On conversion failure, sets `hasFailed` and **deliberately leaves the existing scene alone** — the cell keeps its Mermaid source, so this is recoverable, and overwriting with an empty scene would destroy a diagram that still exists. `retry()` bumps a token to re-trigger the conversion effect. Delegates actual persistence debouncing to `useDiagramPersistence`. |
| `useDiagramCamera` | `(excalidrawAPI) => {isAuto, fitAuto, focus, resume, armAuto, notifyScroll}` | The single owner of camera movement for a diagram canvas — the doc comment is explicit about why "single owner" matters: two independent things moving the camera would fight each other on a resize mid-move. `isAuto` tracks whether auto-fit is still in control; it switches off the moment the student pans/zooms manually (`notifyScroll`) or focuses an element (`focus`), and switches back on via `resume()` (the student explicitly asking for the full diagram back) or `armAuto()` (used right before an action that's about to resize the container anyway, so the fit can happen once against the new size instead of twice). Every programmatic move first raises a suppression flag (`suppressedRef`, cleared after the move's animation duration + a small buffer) — without it, `scrollToContent`'s own emitted scroll events would immediately be read as "the user panned" and switch off auto-fit on the very first automatic fit. |
| `useDiagramFocus` | `(excalidrawAPI, focus) => (selection: DiagramSelection) => void` | Turns a selection into a camera target via the `focus` callback from `useDiagramCamera` (never calls `scrollToContent` directly, to stay behind the single camera owner). A `'node'` selection focuses the node plus its immediate neighbourhood (a lone node fills the viewport and explains nothing on its own); a `'group'` selection (has a `groupId`) focuses every member of that group. |
| `useDiagramPersistence` | `(cellId, sourceRef) => {handleChange, handlePointerUp, markSaved, flush}` | Debounced save for a diagram cell, decoupled from Excalidraw's `onChange` firing rate. `onChange` fires on viewport-only updates too (pan/zoom), not just scene edits — the source comment notes one pan produced 42 calls against a single distinct content hash — so the decision to save is made on `hashElementsVersion()` + a signature of `appState`/`files` (`buildSceneSignature`), not by re-serializing the whole ~29KB scene every call. A changed signature schedules a debounced flush (`SAVE_DEBOUNCE_MS`); `handlePointerUp` (end of a drag/gesture) schedules a shorter flush (`SAVE_SETTLE_MS`) if a save is already pending, letting a just-finished gesture save sooner without racing Excalidraw's own trailing `onChange`. Flushes immediately on `visibilitychange`/`pagehide` (tab hidden or unloading) so nothing is lost on close. |
| `useDiagramSelection` | `() => {selection, sync}` | Tracks the student's current Excalidraw selection, classified into a `DiagramSelection` (`'node'` for a lone element, `'group'` when the selected elements share a real Excalidraw group id — clicking any member of an authored subgraph selects the whole subgraph, not just that element). Only stores identity (`elementId`/`groupId`/`label`), never derived geometry — the comment explains why: `onChange` fires on host re-renders too, and storing something like a position would create a `setState → render → onChange → setState` loop that trips React's "maximum update depth exceeded" safeguard. |
| `useDiagramViewport` | `(wrapperRef, excalidrawAPI, fitAuto) => void` | A single `ResizeObserver` on the canvas wrapper, covering all three ways a diagram cell's container can change size: the fullscreen toggle (never fires `re-resizable`'s `onResizeStop`), a manual resize-handle drag (only reports at drag end), and a window resize. On each (debounced) resize, calls `excalidrawAPI.refresh()` (Excalidraw's own cached position offsets go stale after the container moves — both `scrollToContent` and pointer hit-testing read them) then `fitAuto()`. Skips its own first observation (the initial mount size), since the scene's own initial fit already covers that. |
| `useCanvasChrome` | `(wrapperRef, isReady) => {isCompact, top, right}` | Tracks where Excalidraw has moved its own UI controls, specifically the breakpoint at which it folds them from the top toolbar into a vertical side rail — needed so this app's own overlay controls can follow. Rather than predicting Excalidraw's breakpoints, it **measures**: looks for `.mobile-misc-tools-container` in the DOM (only present in the compact layout) and reads its bounding box via a debounced `ResizeObserver`. Returns `DESKTOP = {isCompact:false, top:0, right:0}` when the rail isn't present. |

## AI tutor chat / RAG UI

| Hook | Signature → Return | Behavior |
|---|---|---|
| `useRagAutoSubmit` | `({cellId, topic, searchTopic, textareaRef, onSubmit}) => void` | Auto-submits a spawned tutor topic. Atomically consumes the target cell id from `useRagStore`, so React development effect replay cannot submit twice. The form repeats `commandsEnabled`; local progress starts before only the server action enters `startTransition`. |
| `useRagCellConversation` | `({cell, state, isPending}) => {topic, messages, origin, searchTopic, pendingQuestion, rememberQuestion}` | Persists a RAG cell's conversation into the cell's own DB-backed content (via `useCellsStore.updateCell`) rather than leaving it only in `useActionState`'s ephemeral result — so it survives a remount, a page reload, or a cross-device sync. Dedupes on `state.timestamp` like the other form-driven hooks. `rememberQuestion(question)` stashes the just-asked question in a ref so it's available once the answer lands (the action's `FormState` doesn't echo the question back). |
| `useRagCellInput` | `() => {textareaRef, slashCommandsEnabled, showResourceAutocomplete, filteredResources, resourceSelectedIndex, resourcesLoading, insertResource, showCommandAutocomplete, filteredCommands, commandSelectedIndex, insertCommand, handleChange, handleKeyDown}` | Composes `useResourceAutocompleteInput` (`@`-mentions) and `useCommandAutocompleteInput` (`/`-commands) into one controller for the tutor's textarea. Command autocomplete takes priority in `handleKeyDown` — resource autocomplete only receives the keydown if no command dropdown is open. `showCommandAutocomplete` is additionally gated on `slashCommandsEnabled` (from `useSettingsStore`) — when the setting is off, a typed `/` is just text, no dropdown appears. |
| `useCommandAutocompleteInput` | `(textareaRef) => {showCommandAutocomplete, filteredCommands, commandSelectedIndex, handleCommandInputChange, handleCommandKeyDown, insertCommand, closeCommandAutocomplete}` | Detects a `/` typed at the start of input or right after a space (not mid-word), filters the static `COMMANDS` list (`@/constants/commands`) by the typed query, and handles `↑`/`↓`/`Enter`/`Tab`/`Escape`. `insertCommand` mutates the **uncontrolled** textarea's DOM value directly and dispatches a synthetic `input` event so React-level `onChange` handlers stay in sync — not a controlled-component update. Designed to be paired with `useResourceAutocompleteInput`; the caller decides which hook's handlers get the event based on which autocomplete is currently open (see `useRagCellInput` above). |
| `useCommandSelection` | `() => {selectedName, command, count, setCount, select, clear, toggle}` | Holds the chip-selected `/command` for one AI cell as a mode (name + item count) rather than free text — per the source comment, so the server reads a form field instead of re-extracting intent from a typed sentence. `select(name)` seeds `count` from the command's own default (`resolveCommandCount`) so the count field is never left empty. `toggle(name)` selects if different, clears if re-clicking the already-selected command. |
| `useResourceAutocomplete` | `() => {resources, loading, error}` | Fetches `/api/mcp/resources` (the current user's notes/materials, see [`14-api-routes.md`](./14-api-routes.md)) once on mount. Uses an `AbortController` tied to the effect's cleanup so an unmount before the fetch resolves doesn't try to `setState` on an unmounted component; an `AbortError` is treated as expected (silently ignored), not logged as a real failure. |
| `useResourceAutocompleteInput` | `(resources: Resource[]) => {textareaRef, showAutocomplete, filteredResources, selectedIndex, handleInputChange, handleKeyDown, insertResource}` | Same `@`-mention pattern as `useCommandAutocompleteInput` (detects `@`, filters, arrow/Enter/Tab/Escape navigation, direct DOM mutation + synthetic `input` event on insert) but filters against the dynamic `resources` list (fetched by `useResourceAutocomplete`) rather than a static command list, and matches against both `displayName` and `name`. Owns the shared `textareaRef` that `useCommandAutocompleteInput` receives as a parameter. |
| `useRagProgress` | `() => {jobId, stage, message, progress, tool, userLogs, technicalLogs, connectionState, isComplete, error, startListening, stopListening, reset}` | Client side of the `/api/rag/progress` SSE stream (see [`14-api-routes.md`](./14-api-routes.md)). State is per-hook-instance (via `useProgressState`, a `useReducer`) rather than a shared store — the doc comment is explicit that this is deliberate, since two concurrent generations (two cells, or a cell and a lecture) each need independent progress rather than one clobbering the other's bar. `startListening()` generates a **fresh `uuidv4()` job id every call** rather than reusing one — necessary because the endpoint returns `204` immediately for a job it already considers complete, so reusing an id after the first run would open a stream that closes instantly and shows no progress on subsequent runs. Splits incoming logs into `userLogs` (audience `'user'` or unset) vs `technicalLogs` (`'technical'`) via `useMemo`. Closes the `EventSource` on unmount. |
| `useRagToolResults` | `({state, cellId}) => void` | After a successful tutor response that produced tool-call results (`state.values.toolResults`, an object keyed by tool name), inserts each result as a new cell below the asking cell via `useInsertGeneratedCell`. Dedupes per-result using a `Set` keyed on `` `${toolName}-${content.slice(0,50)}` `` (a ref, survives re-renders) so a re-render with the same `state` doesn't insert the same generated content twice. |
| `useStickToBottom` | `(containerRef, contentRef) => void` | Keeps a scrolling chat/log container pinned to its bottom as content grows (SSE progress lines, streaming markdown, an expanding answer). Watches the **content box's size** via a `ResizeObserver`, not a dependency array — the source comment explains this is necessary because the triggers for height change (SSE events arriving, markdown finishing layout) aren't expressible as React deps. Unpins the instant the student scrolls up more than `PIN_THRESHOLD_PX = 80` from the bottom, and re-pins once they scroll back down within that threshold — so reading an earlier message is never interrupted by an incoming one yanking the scroll position. |
| `useSpeechRecognition` | `(onResult: (text, isFinal) => void) => {isListening, startListening, stopListening, isSupported}` | Wraps the browser's Web Speech API (`window.SpeechRecognition`/`webkitSpeechRecognition`), configured `continuous: true`, `interimResults: true`, `lang: 'pl-PL'` (Polish only, hardcoded). `isSupported` reflects whether the API exists at all in the current browser — `false` on browsers without it (notably no Firefox support), with no fallback UI decision made by the hook itself. `onResult` is kept in a ref so a new function reference on every render doesn't tear down and recreate the recognizer. On a recognition error, stops listening and logs the error — no retry. |

|---|---|---|
| `useDebouncedValue<T>` (`.tsx`) | `(value: T, delay: number) => T` | Standard debounce: returns a copy of `value` that only updates after `delay` ms without a further change. Backs every React-Query search input per Golden Rule #5 (`useQuestionsQuery`, `useRandomPositions`, etc.). |
| `useDropdownSelect` | `(options: SelectOption[], value: string \| null, onSelect) => {open, activeIndex, setActiveIndex, containerRef, openAt, close, commit, onKeyDown}` | Generic accessible dropdown controller (backs the `Select`/`DropdownSelect` UI primitives). Full keyboard support: `Enter`/`Space`/`ArrowDown` opens when closed; `ArrowUp`/`ArrowDown`/`Home`/`End`/`Enter`/`Space`/`Tab`/`Escape` navigate when open. Includes type-ahead: typing letters within `TYPEAHEAD_RESET_MS = 600` of the previous keystroke accumulates into a search query (`findOptionByPrefix`), reset if the gap is longer. Closes on an outside `mousedown` via a document-level listener while open. |
| `useInfiniteScroll<T>` | `({data, itemsPerPage, threshold=0.1, delay=0}) => {visibleItems, hasMore, isLoading, loadMoreRef}` | `IntersectionObserver`-driven pagination over an **already-fetched, in-memory** list (not a paginated API — everything is loaded, just revealed incrementally). `loadMoreRef` is the sentinel element to observe; crossing `threshold` bumps `displayedItems` by `itemsPerPage` after an optional artificial `delay`. An `isLoadingRef` (not just the `isLoading` state) guards against double-triggering — using `isLoading` state directly in the effect's dependency array would disconnect/reconnect the observer on every load cycle. |
| `useScroll` | `(threshold=50, container?) => {isScrolled, scrollDirection}` | Tracks scroll position of `container` (or `window` if omitted) against `threshold`, plus direction (`'up'`/`'down'`). rAF-throttled (`ticking` flag) so the scroll handler doesn't run more than once per animation frame. Skips a `setState` call if neither `isScrolled` nor `scrollDirection` actually changed. Drives the Navbar's shrink/blur-on-scroll effect. |
| `useScrollToTopOnChange` | `(dependency: unknown) => RefObject<HTMLDivElement>` | Returns a ref to attach to a scrollable container; scrolls it to `{top: 0}` every time `dependency` changes (e.g. switching tabs/pages within a panel). |
| `useCarousel` | `({options?, autoplayDelay=3000}) => {emblaRef, selected, isPlaying, scrollTo, scrollPrev, scrollNext, setIsPlaying}` | Wraps `embla-carousel-react` (used for testimonials). Autoplay via `setInterval`, reading the current `emblaApi` through a ref so the interval doesn't need to re-register every time `emblaApi` itself changes identity. Autoplay is **permanently disabled** the first time the user manually interacts (`pointerDown` sets `isPlaying = false`) — there's no auto-resume after a pause. |
| `useSortedForumPosts` | `(posts: Post[]) => Post[]` | Reads `sortOption` from `useForumSearchStore` (Zustand). `useMemo`'d sort over 4 modes: `newest`/`oldest` (by `createdAt`), `most_comments` (by comment count), `recent_activity` (by the max of the post's own `createdAt` and every comment's `createdAt` — a post with a very recent comment sorts as recently active even if the post itself is old). |
| `useProgressState` | `() => [ProgressState, Dispatch<ProgressAction>]` | Per-instance generation reducer. `start` immediately sets local `parsing`/10% before SSE connects, eliminating the blank auto-submit delay; later SSE events replace it with server progress. |

## Decorative / landing-page animation

| Hook | Signature → Return | Behavior |
|---|---|---|
| `useFloatingShapes` | `({count=5, minSize=25, maxSize=100, minDuration=10, maxDuration=20}) => FloatingShape[]` | Generates `count` randomized decorative shapes (`generateShape()`) from a fixed 3-color palette. Regenerates whenever any config value changes; runs only inside a `useEffect` (not during render) so shape generation never blocks or affects the initial paint. |
| `useRandomPositions` | `(count=6) => {positions, svgSize}` | Generates `count` random `{top, left}` percentage positions **once on mount** (and when `count` changes) — **not** regenerated on resize, per the doc comment. Only `svgSize` is resize-reactive: a debounced (`200ms` via `useDebouncedValue`) `window.innerWidth` listener maps to one of three fixed sizes (`<768px`→20px, `<1024px`→28px, `≥1024px`→36px). |
| `useSparkles` | `(count=30) => Sparkle[]` | Generates `count` sparkle particles (position, size, intensity, color from a 3-shade red palette, and a `delay` staggered evenly across `count` up to 6s) once on mount / when `count` changes. Pure decoration, no resize handling. |
| `useSceneReveal` | `(count: number, once=false) => {active, setScene}` | `IntersectionObserver`-driven reveal sequencing: `active: boolean[]` tracks which of `count` scenes currently cross a `0px 0px -25% 0px` root-margin line; `setScene(index)` returns a ref-callback to attach per scene element. `once=true` latches a revealed item on permanently instead of toggling it back off when it leaves the viewport — needed for scenes inside a `sticky` column that stops moving once pinned (toggling off there would look broken, since the element never actually scrolls away). Used by `PathQuestionList`/`PathShotCollage` (`once=true`) and `PathTimeline` (`once=false`, tracks which step is centered while pinned). |
| `useHorizontalPath` | `(count: number) => {section, viewport, track, percent, near, height, pinned}` | Drives `PathTimeline`'s pin-and-scroll horizontal step track (`/kierunki/[slug]` career-path timeline). Writes the track's `transform` **directly to the DOM style** on every scroll/resize (rAF-throttled), not through React state — re-rendering step cards at 60fps to update one transform would be the difference between smooth and janky. `percent` (0–100, via `clampPercent`) drives the visible progress bar; below the `xl` breakpoint (`1280px`), falls back to a plain vertical list (`pinned: false`, `height: null`), computing `percent` from the section's own scroll position instead of horizontal track travel. `near: boolean[]` marks which step card is currently centered in the viewport. |
| `useWigglyText` | `(text: string, startIdx=1) => {chars, isHoverable}` | Per-character "wiggle" animation for hero/marketing text — replicates a SCSS staggered-animation-delay pattern (`$i / 10s` per character) so multiple adjacent words can continue the same stagger sequence via `startIdx`. `isHoverable` flips to `true` once the full staggered bounce-in animation would have finished (computed from character count + a fixed `0.6s` bounce duration), gating hover interactions until the entry animation has visibly completed. |
