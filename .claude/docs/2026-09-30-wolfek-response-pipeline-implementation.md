# Wolfek response pipeline — implementation

Historical September 30 implementation. The per-button fresh-call policy below is superseded by [October 1 prepared batches](2026-10-01-wolfek-prepared-batches.md). Typed questions still make fresh calls.

2026-09-30. Source implementation complete; live Jev quality/account verification pending Greg.

## Delivered behavior

Kierunki, panel home, results and category-learning questions now use `askWolfekQuestionAction` → `executeWolfekQuestion`. Prepared buttons submit their visible Polish prompt, just like the text form. Old direct-answer actions and topic-only app selectors were removed.

Runtime content lives in `src/content/wolfek/`: four versioned response packs and `questions.json`. The `.claude/reviews` JSON remains the review snapshot, not the deployed request body. Candidate responses are materialized from server-scoped facts before inference. Missing data creates explicit unavailable alternatives; confirmed zero/empty states remain distinct.

Each fresh intentional submission calls Jev with Choice `response`, Noul `needs_clarification`, and Score `answer_coverage`. Only the selected supplied response is rendered. Noul/Score remain diagnostics; they cannot inspect the Choice winner. Existing .35 confidence policy remains pending calibration. Invalid/missing provider output never falls back to a direct FAQ answer.

There is no question-text decision cache. A scoped submission ID deduplicates network retries for five minutes. Retry replay rechecks access and whether the selected response still matches current facts. A deliberate second submission has a fresh ID and another provider call. In-flight duplicate requests report pending instead of calling again.

Initial question-call guards: signed-in 60/minute and 600/hour; anonymous 12/minute and 120/hour. These are starting abuse settings for the larger question-button workload, not measured optimal limits. Automatic practice coaching retains its separate guard and triggers.

## Facts and remaining content

- Course ownership/effective tiers come from existing enrollment logic. Features/offers reuse the maintained catalog/configuration. Course-specific price, tier and video alternatives are instantiated before selection.
- Completed-test count and overall totals are scoped aggregates over the theory results page's records. Category/difficult-question data reuse analytics. Plan, billing, storage and badges reuse scoped helpers.
- A specific results-page test is not silently inferred: absent selected-test context allows clarification/general explanation instead of fabricated details.
- Payment methods remain unconfirmed. Empty video registries produce confirmed unavailable responses. Greg deferred supplying those facts/assets.
- Medical hints/materials remain unavailable when the reviewed support catalog lacks an entry. No medical explanation is generated by Jev.
- Profile-value and personal forum-activity alternatives from the draft are not loaded into route-wide provider state; their editing/navigation questions are implemented. Adding those sensitive detail paths requires a scoped follow-up design.

## Learning behavior

Explicit hint, comparison, AI, next-card and recommendation questions now reach the shared pipeline. Existing card grading/reveal rules remain server-owned; automatic coaching stays on its original adapter.

Reviewed hint exposure is committed before the hint response is returned. Card/session/revision and current eligibility are checked again after inference. Tutor use retains Premium authorization; hidden answers require an explicit reveal-and-tutor confirmation, which itself goes through Jev. Comparison/navigation run only for matching explicit prepared controls. Following an already selected material/plan link is ordinary navigation.

UI controls such as close, minimize, restore, expand and dismiss remain direct controls. Question prompts and currently selected response actions are kept separate.

## Logging and compatibility

No new database columns or migration are required. Provider requests include submission ID and input origin in `state.submission`; the prepared-button ID is not supplied as a selection cue. Application delivery metadata is appended to the existing parsed response JSON as `wolfekDelivery`: origin, prepared-question ID, submission ID, delivery status, displayed answer and action latency. `responseText` preserves the original provider HTTP body.

New button submissions count as questions, not historical `topic_click` events. Manual practice questions also appear in insights. Admin labels distinguish old direct clicks/cache from the new behavior. Audit selection reads the new `answers.response` field and still understands historical records.

Provider success and application delivery success remain separate. A pre-provider failure has an unavailable interaction when it reaches the orchestrator; invalid/unauthorized inputs or failures obtaining submission coordination do not create a provider log. Inspect `wolfekDelivery` for failures occurring after a successful provider response.

## Smoke-test parser correction

Greg reported intermittent errors when switching question buttons. Eight recent Kierunki audit responses were inspected read-only: all HTTP 200, with three recorded as `invalid_response`. Each rejected response contained an allowed winning Choice. The rejection came from the parser's extra arithmetic check comparing reported diagnostic Score with the mean calculated from its displayed probabilities: 2.98 versus 3.00, 2.82 versus 2.80, and 2.79 versus 2.77.

Removed that exact cross-field arithmetic requirement. Score remains a diagnostic; model identity, primitive shapes, bounded numeric values, complete distributions, probability sums and winning response membership remain validated. No timeout, retry or question cache change was needed.

All eight stored responses replay successfully through the corrected parser, including the three previous failures. Fourteen focused regression tests, typecheck and lint passed. No fresh paid inference or log rewriting occurred. Real button clicks after the fix remain Greg's next smoke check.
